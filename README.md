# Сверка врачей

Небольшое приложение на FastAPI и React/TypeScript. Загружает записи из Medical API и HTML-каталога врачей, сопоставляет их и показывает исходные значения рядом.

## Запуск

Для первого запуска нужен локальный файл настроек.

```sh
cp .env.example .env
```

Укажите в `.env` ключ из задания в переменной `MEDICAL_API_KEY`. Файл используется сервером и игнорируется Git.

```sh
docker compose up --build
```

Откройте **http://localhost:8000**. Для повторного запроса к обоим источникам нажмите «Обновить».

Без Docker (Python 3.11+, Node.js 20.19+ или 22.12+):

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
python -m uvicorn --app-dir backend doctor_compare.main:app
```

Для разработки фронтенда запустите `npm --prefix frontend run dev` рядом с запущенным FastAPI и откройте адрес Vite. Swagger доступен по адресу `/api/docs`, схема OpenAPI — по адресу `/api/openapi.json`.

По умолчанию Docker публикует порт только на локальном интерфейсе. Адрес и порт можно задать переменными `APP_BIND` и `APP_PORT`.

## Как работает сверка

Сервер загружает до 200 уникальных записей Medical API и до трёх первых страниц Doctor Catalog. Карточки каталога извлекаются из HTML. Поиск по ФИО и специальности и фильтр по статусу работают по загруженной выборке.

Перед сравнением сервер приводит текст к одному регистру, заменяет `ё` на `е` и выделяет слова. Для специальностей он также учитывает префикс «врач» и несколько синонимов, например «лор» и «оториноларинголог».

- **Совпало.** Совпадают специальность и все части полного ФИО в том же порядке. Для этой проверки полное ФИО содержит хотя бы три части без инициалов. Сервер выбирает точную пару после сбора всех кандидатов и только если обе записи подходят исключительно друг другу.
- **Возможно совпадение.** При одинаковой специальности учитываются одинаковые неполные ФИО, перестановки частей, инициалы при одной совпавшей полной части и опечатка в одной части полного ФИО. Различия и пропуски в дополнительных частях допустимы, если имя и фамилия из отдельных полей Medical API присутствуют в обеих записях. Полное ФИО с теми же частями также даёт кандидата при отсутствующей или другой специальности. Если у любой записи в паре есть ещё один кандидат по этим правилам, все варианты остаются доступны для ручной проверки. Страница показывает причины и позволяет переключаться между кандидатами из каталога.
- **Только в Medical API (в выборке) / Только в Doctor Catalog (в выборке).** Для записи в загруженной выборке пары или кандидата не нашлось.

Таблица показывает ФИО, специальность и стаж в двух источниках, а также клинику и публичную цену из каталога, если они указаны. Различия подсвечиваются по отображаемым значениям. Статусы описывают результат сравнения записей по этим правилам.

Сервер хранит последний успешный отчёт в памяти и использует его до минуты при открытии страницы. Кнопка «Обновить» запускает загрузку из обоих источников. При ошибке страница сохраняет уже показанный отчёт.

## Проверки

```sh
python -m pip install -r backend/requirements-dev.txt
python -m pytest
npm --prefix frontend run build
```

Тесты используют подставные ответы источников. Для проверки с реальными данными нужны доступ к обоим источникам и действующий ключ.
